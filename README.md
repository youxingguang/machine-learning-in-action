机器学习面试指南（基础部分）

机器学习概述

1.1 什么是机器学习
机器学习定义：机器学习是让计算机系统从经验（数据）中自动学习并改进性能，而无需显式编程。其核心思想是通过算法从数据中发现模式，并用于对新数据进行预测或决策。
机器学习 vs 传统编程：
  传统编程：输入规则 + 输入数据 → 输出结果。
  机器学习：输入数据 + 期望输出 → 学习规则（模型）→ 对新数据预测。
数据驱动的建模方式：模型性能高度依赖于数据质量与数量，强调“用数据说话”，而非完全依赖领域专家手工制定规则。

1.2 机器学习三大范式
监督学习（Supervised Learning）：训练数据包含输入特征和对应标签（如分类、回归）。目标是学习一个映射函数  f: X rightarrow Y 。
无监督学习（Unsupervised Learning）：训练数据只有输入特征，无标签（如聚类、降维）。目标是发现数据内在结构或分布。
强化学习（Reinforcement Learning）：智能体在环境中通过试错学习策略，以最大化长期累积奖励。典型应用包括游戏 AI、机器人控制等。

1.3 常见机器学习任务
分类问题：输出为离散类别（如垃圾邮件识别、图像分类）。
回归问题：输出为连续数值（如房价预测、温度预测）。
聚类问题：将相似样本分组（如用户分群、异常检测）。
排序问题：对候选集按相关性打分排序（如搜索引擎结果排序）。
推荐问题：根据用户历史行为预测其可能感兴趣的物品（如电商推荐、视频推荐）。

完整机器学习流程（ML Pipeline）

2.1 问题定义（Problem Definition）

2.1.1 业务问题转化为机器学习问题
输入数据是什么：明确可用的特征来源（如用户行为日志、商品属性等）。
预测目标是什么：确定模型要预测的内容（如点击率、流失概率）。
是否有标签：判断是否具备监督信号，决定能否使用监督学习。

2.1.2 任务类型判断
分类：目标变量为类别（二分类/多分类）。
回归：目标变量为实数。
排序：需对多个候选对象排序（常用于信息检索）。
聚类：无标签场景下探索数据结构。

2.1.3 常见问题
目标定义不清晰：如“提升用户体验”过于模糊，需量化为具体指标（如点击率、停留时长）。
标签噪声：人工标注错误或自动标签不可靠，影响模型学习。
评价指标错误：例如在极度不平衡数据中使用 Accuracy 作为主要指标。

数据收集（Data Collection）

3.1 数据来源
数据库：结构化业务数据（如 MySQL、Hive）。
日志系统：用户行为日志（如埋点数据、Nginx 日志）。
API：第三方服务接口（如天气 API、社交平台 API）。
爬虫：从网页抓取非结构化数据（需注意合规性）。
开源数据集：如 Kaggle、UCI、ImageNet 等。

3.2 数据规模问题
小数据问题：样本量少，易过拟合，需采用正则化或迁移学习。
长尾数据问题：少数类别样本极少，导致模型对尾部类别表现差。
类别不平衡：正负样本比例悬殊（如欺诈检测中欺诈样本占比  3 视为异常。
IQR方法：Q1 - 1.5×IQR 到 Q3 + 1.5×IQR 之外视为异常。
Winsorization：将极端值截断至指定分位数（如 1% 和 99%）。

5.3 重复数据处理
去重：删除完全相同的记录（基于主键或全字段）。
聚合：对重复但含增量信息的记录进行汇总（如多次点击合并为总次数）。

5.4 数据格式统一
时间格式：统一为 ISO 8601（如 2025-03-16T10:00:00）。
编码格式：统一为 UTF-8，避免乱码。
单位统一：如将“公里”和“米”统一为“米”。

5.5 常见问题
过度清洗导致信息丢失：如盲目删除所有含缺失值的样本。
错误填充引入偏差：如用全局均值填充分组数据（应分组填充）。
数据泄漏：在清洗阶段使用了测试集信息（如用全集均值填充）。

特征工程（Feature Engineering）

6.1 特征构造
组合特征：如 age × income 表示消费能力。
统计特征：如用户过去7天平均点击次数、最大值、标准差。
时间特征：如星期几、是否节假日、小时段（morning/evening）。

6.2 特征变换
标准化（Standardization）： x' = frac{x - mu}{sigma} ，适用于线性模型、SVM、神经网络。
归一化（Normalization）： x' = frac{x - x_{min}}{x_{max} - x_{min}} ，适用于距离敏感模型（如 KNN）。
Log变换：缓解右偏分布，使数据更接近正态。

6.3 类别特征处理
One-Hot Encoding：将类别转为稀疏二值向量，适用于低基数类别。
Label Encoding：将类别映射为整数，适用于树模型（但隐含序关系）。
Target Encoding：用目标变量的统计量（如均值）编码类别，需防过拟合（如加平滑）。

6.4 特征选择
Filter 方法：基于统计指标（如卡方、互信息）筛选特征。
Wrapper 方法：通过模型性能评估子集（如递归特征消除 RFE），计算成本高。
Embedded 方法：模型训练过程中自动选择特征（如 Lasso、XGBoost 内置重要性）。

6.5 常见问题
特征维度过高：导致“维度灾难”，增加训练时间和过拟合风险。
特征冗余：多个高度相关特征浪费资源，降低模型效率。
特征泄漏：使用了未来信息或目标变量本身构造特征（如用“订单总额”预测“是否下单”）。

数据集划分（Dataset Split）

7.1 数据划分方法
Train / Validation / Test：通常按 70%/15%/15% 或 80%/10%/10% 划分，验证集用于调参，测试集用于最终评估。
K-Fold Cross Validation：将训练集分为 K 份，轮流用 K-1 份训练、1 份验证，适用于小数据集。

7.2 时间序列数据划分
必须按时间顺序划分，禁止随机打乱。例如：用前 80% 时间数据训练，后 20% 验证。

7.3 类别不平衡处理
过采样：复制少数类样本（如 RandomOverSampler）。
欠采样：随机删除多数类样本。
SMOTE：在少数类样本间插值生成新样本，缓解过拟合。

7.4 常见问题
数据泄漏：划分时未隔离时间或用户 ID，导致同一用户出现在训练和测试集。
训练集和测试集分布不同：如训练用旧数据、测试用新数据，但未考虑分布漂移。

模型选择（Model Selection）

8.1 基线模型（Baseline Model）
简单模型作为参考：如逻辑回归、平均预测、众数预测。用于判断复杂模型是否真正带来提升。

8.2 模型类型选择
线性模型：如 Logistic Regression、Linear Regression，可解释性强，适合线性可分问题。
树模型：如 Decision Tree、Random Forest、XGBoost，对特征缩放不敏感，擅长处理非线性与交互。
神经网络：适合高维、复杂模式（如图像、文本），但需要大量数据和调参。

8.3 偏差-方差权衡
高偏差：模型太简单，欠拟合（如用线性模型拟合非线性数据）。
高方差：模型太复杂，过拟合（如深度树在小数据上）。
目标：在两者间取得平衡，使泛化误差最小。

8.4 常见问题
模型过于复杂：在小数据上使用深度神经网络，导致过拟合。
模型欠拟合：特征不足或模型容量太低。
选择模型不匹配任务：如用回归模型解决分类问题。

模型构建（Model Training）

9.1 模型训练流程
定义模型：选择算法结构（如 XGBoost、MLP）。
定义损失函数：如交叉熵（分类）、MSE（回归）。
优化算法：如 SGD、Adam，用于最小化损失函数。

9.2 训练技巧
Batch训练：分批加载数据，节省内存，稳定梯度。
学习率调度：如 Step Decay、Cosine Annealing，加速收敛。
Early Stopping：当验证损失不再下降时提前终止，防止过拟合。

9.3 正则化方法
L1：Lasso，可实现特征选择（稀疏解）。
L2：Ridge，抑制权重过大，提升泛化。
Dropout：神经网络中随机屏蔽神经元，增强鲁棒性。

9.4 常见问题
梯度消失：深层网络中梯度趋近于 0，导致训练停滞（可用 ReLU、残差连接缓解）。
梯度爆炸：梯度极大，参数更新不稳定（可用梯度裁剪）。
训练不收敛：可能因学习率过大/过小、数据未归一化、损失函数设计错误。

模型评估（Model Evaluation）

10.1 分类指标
Accuracy：正确预测比例，不适用于不平衡数据。
Precision：预测为正例中真实为正的比例（关注假阳性）。
Recall：真实正例中被正确预测的比例（关注假阴性）。
F1-score：Precision 与 Recall 的调和平均。
ROC-AUC：衡量模型在不同阈值下的整体判别能力。

10.2 回归指标
MAE（Mean Absolute Error）：平均绝对误差，对异常值不敏感。
MSE（Mean Squared Error）：平方误差均值，放大异常值影响。
RMSE：MSE 的平方根，单位与目标一致。
R²：决定系数，表示模型解释的方差比例（越接近 1 越好）。

10.3 模型诊断
混淆矩阵：展示各类别的预测与真实对比。
ROC曲线：TPR vs FPR 曲线，AUC 为其下面积。
Precision-Recall曲线：在正样本稀少时比 ROC 更具参考价值。

10.4 常见问题
指标选择错误：如在医疗诊断中只看 Accuracy，忽略 Recall。
数据不平衡导致误判：高 Accuracy 掩盖模型对少数类的失效。
过拟合：训练指标很好，验证指标差。

模型调优（Hyperparameter Tuning）

11.1 参数搜索方法
Grid Search：遍历所有参数组合，计算成本高。
Random Search：随机采样参数组合，效率更高（尤其当某些参数影响更大时）。
Bayesian Optimization：基于历史结果建模目标函数，智能选择下一个参数点。

11.2 自动调参
AutoML：如 Google AutoML、H2O.ai、Optuna，自动完成特征工程、模型选择与调参。

11.3 常见问题
调参空间过大：参数组合爆炸，耗时过长。
过度调参导致过拟合：在验证集上反复优化，导致模型对验证集过拟合。

模型解释（Model Interpretation）

12.1 特征重要性
Tree Feature Importance：基于特征分裂带来的不纯度减少（如 Gini Importance）或排列重要性（Permutation Importance）。

12.2 可解释性方法
SHAP（SHapley Additive exPlanations）：基于博弈论，提供每个特征对单个预测的贡献值。
LIME（Local Interpretable Model-agnostic Explanations）：在局部拟合可解释模型（如线性模型）解释黑盒预测。

12.3 常见问题
黑盒模型不可解释：如深度神经网络难以说明“为何做出此预测”。
特征贡献误解：如将相关性误认为因果性，或忽略特征交互效应。

模型部署（Model Deployment）

13.1 部署方式
Batch Prediction：定期批量处理数据（如每日用户画像更新）。
Online Prediction：实时响应请求（如推荐系统、风控拦截）。

13.2 服务架构
REST API：通过 HTTP 接口提供预测服务，易于集成。
微服务：将模型封装为独立服务，支持弹性扩缩容。

13.3 模型版本管理
使用 MLflow、DVC 或自建系统管理模型版本、参数与性能记录，支持回滚与 A/B 测试。

13.4 常见问题
推理延迟：模型太大或计算复杂，无法满足实时性要求。
资源消耗过高：GPU/CPU 内存占用大，部署成本高。

模型监控（Model Monitoring）

14.1 数据漂移（Data Drift）
指输入特征分布随时间发生变化（如用户年龄结构变化），可通过 KS 检验、PSI（Population Stability Index）监测。

14.2 概念漂移（Concept Drift）
指输入与输出之间的关系发生变化（如疫情后用户购物偏好改变），即使数据分布不变，模型性能也会下降。

14.3 模型性能监控
实时跟踪关键指标（如 Precision、Latency、QPS），设置告警阈值。

14.4 模型再训练
当性能显著下降或检测到漂移时，触发自动或手动再训练流程。

14.5 常见问题
模型性能下降：未及时发现漂移，导致线上效果恶化。
数据分布变化：未同步更新特征工程逻辑，造成输入不一致。
